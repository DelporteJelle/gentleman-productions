# Regenerate API Client

## Overview

The frontend's typed SDK, Zod schemas, and TanStack Query `queryOptions` are **auto-generated** from `backend-pulse`'s OpenAPI spec (and optipack's, where applicable). After any change to a backend router, request/response model, or status code, regenerate before writing the FE code that consumes the new shape.

**Announce at start:** "I'm using the regenerate-api-client skill to run the typegen ritual."

## The Ritual

### 1. Verify `backend-pulse` is running on port 8001

`yarn typegen` pulls the OpenAPI spec from a live local backend — the generator does not introspect Python code.

```bash
curl -s http://localhost:8001/openapi.json > /dev/null && echo OK
```

If that fails, start the backend in another shell from `backend-pulse/`:

```bash
cd backend-pulse && python -m fastapi dev --port 8001
```

Wait for the Uvicorn "Application startup complete" line before running typegen.

### 2. Run typegen

From `frontend/`:

```bash
cd frontend && yarn typegen
```

This rewrites the files under `frontend/src/api/client/` (and `frontend/src/api/optipack/client/` if the optipack source changed — see below). Both paths are read-only by convention; see [`.claude/rules/generated-paths.md`](../../rules/generated-paths.md) for the enforcement list.

### 3. Verify the regen by content

`frontend/src/api/client/` is gitignored (see `frontend/src/api/.gitignore`) and regenerated by `yarn build` in CI, so `git diff` will not show the change. Use a content check instead:

```bash
grep <new_method_name> frontend/src/api/client/sdk.gen.ts
```

`yarn typecheck` against the FE consumer code is the surest signal that the regen took. A stale or wrong backend produces sweeping unrelated SDK shapes that show up as a tide of typecheck errors at the call sites — that's the symptom of "regenerated against the wrong spec," see Troubleshooting.

### 4. Optipack client (separate, only when needed)

Optipack is a sibling repo. Its generated output sits at `frontend/src/api/optipack/client/`. Regenerate it **only** when you've pulled optipack changes or the optipack spec URL is what drove your task — not on every BE-pulse change. The command is the same `yarn typegen` (the FE script targets both specs); if you want a pure BE-pulse refresh, inspect the optipack portion of the diff and discard it if unrelated.

## What gets committed

Nothing under `frontend/src/api/client/` — the path is gitignored and regenerated by `yarn build` (which runs `yarn typegen` first). Your commit contains either the backend change that produced the new spec, OR the FE code consuming the new shape (hooks, components, pages). CI's rebuild step keeps the deployed client consistent; there is no committed snapshot to drift. See [`.claude/rules/frontend-after-backend.md`](../../rules/frontend-after-backend.md) for the gate.

## Never hand-edit generated files

The `block-generated-api` hook rejects `Write` / `Edit` tool calls targeting any path listed in [`.claude/rules/generated-paths.md`](../../rules/generated-paths.md). If you find yourself wanting to "just tweak one line" in `frontend/src/api/client/`, the correct move is:

1. Change the backend to produce the shape you want.
2. `yarn typegen`.
3. Move on.

Tweaking the generator output locally = drift on the next regen.

## Troubleshooting

### `yarn typegen` fails with connection refused

Backend isn't on port 8001. Start it (see step 1) and retry. If another process occupies 8001, kill it (`lsof -i :8001`) rather than choosing a different port — the typegen config points at 8001.

### `yarn typegen` fails with an OpenAPI parse error

The backend introduced an invalid spec. Common causes:

- A response model references a Pydantic type with a forward reference that didn't resolve.
- A router uses `response_model=dict` without schema hints, producing `{}` that the generator can't type.
- A duplicate operation ID (two routes with the same function name under the same router).

Fix the backend first — the generator is not the bug. `curl -s http://localhost:8001/openapi.json | python -m json.tool` helps spot the malformed section.

### Regenerated diff is huge and unrelated

You're pointed at the wrong backend. Scenarios:

- A stale `fastapi dev` from an older branch is still running on 8001.
- A teammate's tunnel-forwarded backend is bound to 8001 (rare but happens).
- You ran typegen from a worktree that still has `backend-pulse` checked out on a different branch, while the running backend reflects that branch.

Kill all local backends, re-start from the current branch's `backend-pulse`, and rerun. If the diff is still huge, `git log -p -- frontend/src/api/client/` on the base branch — the delta may be real migration churn, in which case rebase.

### Generated files mismatch in CI / local consumer code

CI runs `yarn build` which regenerates the client against the current backend spec. Drift surfaces locally as typecheck errors at FE call sites that read fields from the new SDK shape. If you see those errors after a backend change, you skipped step 2 — rerun `yarn typegen` and your FE typecheck.
